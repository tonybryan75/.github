# Contributing

Thanks for your interest. These are the default contribution guidelines for
[@tonybryan75](https://github.com/tonybryan75) repositories; an individual repo may add its own.

## Workflow

Most of these repos follow a spec-driven development process (captured per-repo in `CLAUDE.md`
routing rules and an `/adr` decision log). In short:

1. **Agree before you build.** Significant changes start from a reviewed proposal/spec, not a diff.
2. **Record decisions.** Architecturally significant, hard-to-reverse choices get an ADR.
3. **Verify, don't assert.** "Done" means observed evidence — tests, build, actual behaviour.
4. **Work in the open.** Branch from a clean baseline; keep PRs small and reviewable.

## Pull requests

- Keep changes focused; one logical change per PR.
- Make sure CI is green before requesting review.
- Fill in the PR template.

## Reporting issues

Use the issue templates. For security-sensitive reports, see [SECURITY.md](./SECURITY.md) instead.
